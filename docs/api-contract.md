# HTTP API

Базовый путь `/api`. Успешные ответы — JSON, кроме DELETE (204 без тела).
Ошибки: `{"error":{"code":"VALIDATION_ERROR","message":"…"}}`.

| Метод и путь | Результат |
|---|---|
| GET /health | 200: status и storage |
| GET /tickets | 200: список, новые первыми |
| GET /tickets/:id | 200: заявка или 404 |
| POST /tickets | 201: заявка, Location: /api/tickets/:id |
| PATCH /tickets/:id | 200: изменённая заявка |
| DELETE /tickets/:id | 204; повторное удаление — 404 |
| GET /tickets/:id/events | 200: история, новые события первыми |
| GET /equipment | 200: справочник оборудования |
| GET /stats | 200: total, equipment, byStatus |

Фильтры списка объединяются через AND: `status=new|in_progress|closed`,
`scope=all|open`, `q` — подстрока заголовка без учёта регистра, до 120 символов
после удаления крайних пробелов. Пустой status означает отсутствие фильтра.
Неизвестные и повторяющиеся параметры запрещены. `%`, `_` и `=` в поиске — буквальные символы.

POST принимает обязательные `title` (3–120 символов после trim) и `equipmentId`
(положительное целое, существующее оборудование), необязательное `description`
(до 2000 символов после trim, по умолчанию пустая строка). Статус назначает сервер: `new`.
PATCH принимает непустое подмножество этих полей и `status`.
Неизвестные поля, null и массив вместо объекта дают 400. Неверный Content-Type — 415,
повреждённый JSON — 400, тело больше 32 KiB — 413.

Сервер возвращает `id`, `equipmentId`, `title`, `description`, `status`,
`equipmentName`, `inventoryNumber`, `createdAt`, `updatedAt`. Даты — ISO 8601 в UTC.
История содержит `id`, `action`, `message`, `createdAt`.
Создание/изменение заявки и соответствующее событие атомарны в MySQL.
Удаление каскадно удаляет историю; ошибка БД даёт 503 без внутренних деталей.
